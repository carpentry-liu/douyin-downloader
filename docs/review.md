# v0.3 代码审查

v0.3.1 目录归档改动的人工复核与回归结果见 [F-0004 验证](features/F-0004-download-folders/04-测试.md)。

日期：2026-09-22。

## 方法与范围

使用 open-code-review 1.11.6 的 `ocr delegate preview` 获取差异范围，`ocr delegate rule` 获取 Python 审查规则，由开发代理逐项人工检查、复现并修复。用户明确选择此方式。

没有调用独立 LLM 审查服务：`ocr llm test` 报告所选 siliconflow provider 未配置。本记录不代表独立模型自动审查通过。CLI 同时提示本机 Git 2.31 低于其推荐最低版本；规则和预览命令正常完成。

检查本次 UI、入口、打包与验收改动，另读入完整平台解析、下载、素材和合成模块。重点包括线程与 Tk 生命周期、离线边界、路径和文件完整性、错误状态、公开仓库内容、构建可复现性。测试文件虽被 OCR 默认预览过滤，仍人工检查并运行。

## 确认的问题和处理

| 优先级 | 问题 | 修复与验证 |
|---|---|---|
| 高 | 旧 `--offline` GUI 没有将离线状态传入窗口；规范链接可经浏览器子进程尝试联网 | 入口传入 offline；禁用下载按钮，控制器和快捷键共同校验；新增真实 Tk 测试确认不调用下载服务 |
| 中 | 首版新布局在普通窗口下挤掉主按钮，用户无法开始下载 | 主操作区优先分配底部空间，输入区使用剩余空间；真实窗口检查默认和最大化布局 |
| 中 | 成品验收依赖开发者已有媒体，同一成品反复运行可能复用旧结果 | 改成动态生成图片、实况、音轨；每次创建新的验收目录，先校验 EXE 哈希；真实联网验收链接通过可选参数传入 |
| 中 | 素材清单顶层为列表或 null 时抛出 AttributeError，用户只看到泛化失败 | 校验顶层与媒体条目类型，给出选择有效素材目录的错误；添加四种损坏清单回归用例 |
| 中 | 旧公开文档与 Git 历史含机器路径、个人媒体记录，不适合整体原样推送 | 公开分支使用干净历史和明确文件白名单，保留完整自研源码/测试/构建说明，历史私人记录留在本地 |

新增 Tk 测试最初出现前一实例的循环引用由下一工作线程回收，导致 Tcl 异常。测试夹具改为在主线程显式释放引用并回收，后续全量测试通过；这不是将异常日志隐藏。

## 结论

上述确认的问题均已修复，没有遗留的已确认高、中优先级代码问题。联网复验中，普通视频成功，但一个图文样本两次未能取得平台数据，原因尚未定位，不能据此宣称图文端到端全部通过。自动测试、实际 EXE 和窗口检查结果见 [验证记录](validation.md)。本次审查不是正式安全审计；平台后续接口变化仍需要维护。
